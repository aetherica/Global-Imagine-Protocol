# GIOP V3.1 — Roadmap Policy

Status: CANONICAL

## Purpose

Sequence GIOP work by dependency and responsibility rather than by arbitrary page count.

## Current rule

The locked tree architecture is stable. Future work populates and validates the existing responsibilities before introducing structural change.

## Dependency principle

Foundation establishes project rules and boundaries first. Semantics establishes canonical meaning. Registry establishes canonical identity. Domain and implementation work then builds on those authorities.

## Version planning

Minor and patch work may deepen, correct, validate, or expand the knowledge within the existing architecture. Major architectural changes require explicit architectural proof and a versioning decision.

The roadmap is a planning instrument, not semantic authority.
