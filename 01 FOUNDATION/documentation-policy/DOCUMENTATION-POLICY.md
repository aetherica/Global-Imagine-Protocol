# GIOP V3.1 — Documentation Policy

Status: CANONICAL

## Purpose

Define how GIOP documentation communicates the same knowledge to general readers, professionals, researchers, engineers, machines, and AI systems.

## Core rule

One body of knowledge, many ways of reading it.

The novice and the expert are not given different knowledge. They are given different entry depths into the same knowledge.

## Documentation layers

Identity/metadata → 5W1H orientation → domain-specific technical depth → trust/provenance → lifecycle → relations/retrieval.

## Requirements

Documentation must distinguish normative requirements, explanations, examples, implementation notes, historical statements, claims, evidence, and warnings.

Use stable headings, explicit definitions, controlled terminology, resolvable cross-references, visible lifecycle state, and machine-readable identity where applicable.

Repository paths support navigation; canonical identity must remain stable independently of path changes.
