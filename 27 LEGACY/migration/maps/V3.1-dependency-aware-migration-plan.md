# GIOP V3.1 — Dependency-Aware Migration Plan

Status: WORKING EXECUTION PLAN
Baseline: V3.0 main
Branch: v3.1-tree-architecture
Principle: establish dependencies and validation gates before content promotion.

## Dependency layers

L0 — Preservation
- main/V3 baseline remains untouched.
- V3 source artifacts remain addressable.
- 27 LEGACY/v3 preservation surface exists.
Gate: no destructive changes.

L1 — Foundation and identity
- 01 FOUNDATION architecture/versioning/governance.
- 02 SEMANTICS foundational ontology, classes, properties, quantities, units, relations.
- 03 REGISTRY identity, versions, mappings, provenance.
Gate: canonical identity model defined before registrations.

L2 — Trust and validation
- 21 RESEARCH claims/evidence/validation.
- 22 STANDARDS source/conformance/mappings.
- 26 TRUST integrity/hashing/provenance/audit.
- tests/ontology, registry, identity, golden-graph, regression.
Gate: promotion cannot occur without provenance and validation status.

L3 — Scientific foundations
- 04 PHYSICS
- 05 OPTICS
- 06 SENSOR-SCIENCE
Gate: physical/scientific claims mapped to evidence where required.

L4 — Acquisition and representation
- 07 CAPTURE
- 08 LENS-SYSTEMS
- 09 REPRESENTATION
Gate: device/lens/capture identities resolve through registry.

L5 — Computation and AI
- 10 COMPUTATION
- 11 AI
- 12 VISION
Gate: distinguish mathematical definition from implementation and perceptual model.

L6 — Professional/application domains
- 13 CINEMATOGRAPHY
- 14 VFX
- 15 PROMPT-ENGINEERING
- 16 IMAGING-DOMAINS
Gate: workflow/domain material references canonical entities rather than duplicating them.

L7 — Delivery/ecosystem
- 17 IMMERSIVE
- 18 MEDIA
- 19 DISPLAY
- 20 SENSOR-ECOSYSTEM
Gate: formats, display profiles, metadata and distributed sensing reference canonical registry identities.

L8 — Implementation
- 23 ENGINEERING
- 24 RUNTIME
- schemas, API, SDK, tools, scripts
Gate: implementation is derived from approved semantics/registry, not the reverse.

L9 — Business and historical
- 25 COMMERCIAL
- 27 LEGACY
Gate: legal/commercial and historical statuses remain distinct from active semantics.

## V3 artifact migration order

1. Register artifact identities and source provenance.
2. Establish semantic primitives used by those artifacts.
3. Validate source claims and external standard references.
4. Promote canonical device/formula/standard/display/component identities.
5. Create scientific/technical responsibility views.
6. Create derived computation/runtime/application projections.
7. Create API/SDK/site/docs projections.
8. Mark superseded/historical material without deleting source history.

## Deferred high-risk promotion

- family-level camera names that are not unique instances
- emerging computational lenses
- AI/optical hybrid concepts
- claims lacking evidence
- historical settings presented as current normative requirements
- vendor-specific software entries whose type (product/API/workflow/plugin) is ambiguous

## V3.1 execution gates

Gate 1: inventory complete.
Gate 2: canonical identity assigned or unresolved explicitly.
Gate 3: provenance recorded.
Gate 4: validation/review status recorded.
Gate 5: destination responsibility confirmed.
Gate 6: duplicate semantic authority check passes.
Gate 7: content promotion only after all previous gates pass.
