# BIL Integrity Profile

**Semantic ID:** `SEM-BIL-INTEGRITY-PROFILE-001`  
**Preferred Name:** Integrity Profile  
**Semantic Class:** BIL Control Concept / Profile  
**Domain:** Biological / Configurational Integrity  
**Status:** Candidate  
**Version:** 0.2.0

> **Integrity Profile** is a declared application/context specification that selects the relevant integrity dimensions, reference requirements, permitted variations, evidence classes, validation methods and decision policies for a use case without creating a new BIL semantic identity.

## 5W1H Orientation

### What
A context-specific configuration of BIL scope and policy.

### Why
Human portrait, wildlife, sports, dance, VFX, scientific imaging and video do not require identical evidence or tolerances. Profiles adapt application without changing the core semantics.

### Who
Practitioners, scientists, validation engineers, VFX supervisors, system designers and machine retrieval systems.

### Where
Human, animal/wildlife, plant/organism, multi-organism, sports, dance/performance, fashion, documentary, scientific/medical, VFX, digital-human, synthetic-creature, still, video and 3D/4D contexts.

### When
Selected at evaluation or retrieval time according to declared task and content context.

### How
`Profile → Scope + Evidence + Variation + Validation + Decision Policy`.

## Semantic Definition

**Integrity Profile** is the BIL control concept that declares context-dependent integrity scope and evaluation policy while preserving one underlying BIL semantic model.

## Core Distinctions

Profile ≠ ontology; ≠ genre ontology; ≠ separate knowledge base; ≠ visitor audience ontology; ≠ implementation model.

## Scope and Boundary

Profiles may activate different integrity dimensions such as identity, structure, state, interaction, appearance, physical, temporal, cross-view and contextual consistency. Profile parameters do not become universal BIL laws.

## Cross-Domain Significance

Profiles route existing GIOP Classes, Properties, Conditions, States, Relations, Quantities, Activities, Representations, Temporal semantics, Workflows, Methods and Provenance into an integrity context.

## Trust and Evidence

Profile identity, version, provenance, scope and validation status must be explicit. Profile changes require revalidation of dependent decisions.

## Visitor Universe

Profile selection is navigation/context metadata. D0 gives the concept, D1 explains profile purpose, D2 uses a profile, D3 exposes parameters, D4 exposes stable profile IDs and machine policy fields.
