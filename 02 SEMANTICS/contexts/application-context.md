# Application Context

**GIOP ID:** `SEM-CONTEXT-APPLICATION-001`  
**Artifact Type:** Canonical Semantic Concept  
**Status:** CANONICAL  
**Primary Responsibility:** Use/task frame

## 5W1H Orientation

**What:** The concrete purpose, task, use scenario, or application setting in which a semantic element is used, interpreted, or evaluated.

**Why:** Meaning and relevance can depend on what an entity, representation, measurement, or process is being used to accomplish.

**How:** By identifying intended use, task, operational objective, constraints, actors, and relevant outputs.

**Where:** Imaging, measurement, processing, assessment, production, deployment, documentation, integration, and decision workflows.

**Who:** Users, operators, systems, organizations, evaluators, and machine consumers.

**When:** During a defined use or evaluation scenario where purpose affects interpretation or requirements.

## Canonical Definition

**Application Context is a contextual frame specifying the concrete purpose, task, use scenario, or application setting in which a semantic element is used, interpreted, or evaluated.**

## Scope

Application Context can specify why a camera, representation, measurement, algorithm, or result is being used and under what application constraints. It does not itself define the workflow or application software.

## Components

Potential components include purpose, task, use case, actors, target outputs, constraints, environment, interfaces, acceptance criteria, and relevant domain context.

## Distinctions

Application Context differs from Domain Context: domain identifies the knowledge universe; application identifies concrete use. It differs from Operational Context: operational context describes circumstances/constraints of operation, while application context emphasizes purpose and use. It differs from Activity/Process: those describe what is done or transformed.

## Cross-Layer Relations

Application Context may qualify activities, processes, measurements, representations, system operation, and evaluation. It can reference Domain Context and relevant contextual access/navigation considerations.

## Evidence / Provenance

Supported by ISO/IEC 11179 context traditions describing purpose and perspective of use and by context-aware computing and GIOP workflow analysis.

## Trust / Validation

Validate that the proposed frame expresses a genuine application purpose or use scenario rather than merely naming an activity, system, or audience.

## Lifecycle

**CANONICAL — V3.1.**

## Machine / AI Interpretation

Use Application Context as a qualification for retrieval, recommendation, configuration, evaluation, and interpretation. Do not infer semantic identity solely from a use case.

## Retrieval Anchors

`application context`, `use context`, `use case`, `task context`, `purpose`, `application scenario`.

## What This Context Does Not Mean

Not a visitor class, software application, workflow, activity, process, domain, or operating condition.

## Semantic Boundary

`APPLICATION CONTEXT = concrete purpose/use frame`

`DOMAIN CONTEXT = knowledge universe`

`ACTIVITY/PROCESS = what is done/transformed`

`OPERATIONAL CONTEXT = circumstances/constraints of operation`
