# Domain Context

**GIOP ID:** `SEM-CONTEXT-DOMAIN-001`  
**Artifact Type:** Canonical Semantic Concept  
**Status:** CANONICAL  
**Primary Responsibility:** Knowledge-domain frame

## 5W1H Orientation

**What:** The knowledge universe, disciplinary scope, subject domain, or conceptual field in which an item is defined or interpreted.

**Why:** The same designation or concept may carry different scope or meaning across domains; domain context makes the intended universe of discourse explicit.

**How:** By identifying the relevant subject field, disciplinary boundaries, conceptual scope, and applicable terminology.

**Where:** Terminology, semantic modeling, data governance, scientific and technical knowledge, documentation, and cross-domain integration.

**Who:** Domain experts, authors, institutions, systems, and machine consumers may establish or use a Domain Context.

**When:** When meaning, applicability, terminology, or interpretation depends on a defined knowledge universe.

## Canonical Definition

**Domain Context is a contextual frame identifying the knowledge universe, disciplinary scope, subject domain, or conceptual field within which a semantic element is defined, interpreted, or used.**

## Scope

Domain Context concerns semantic scope rather than physical location. It can identify imaging science, color science, metrology, computer vision, broadcast engineering, archival practice, or another subject field without redefining that field's concepts.

## Components

Relevant components may include subject domain, discipline, subdomain, terminology system, conceptual scope, governing conventions, applicable standards, and intended expert community.

## Distinctions

Domain Context is not an ontology, class, vocabulary term, namespace, application, physical environment, or visitor category. A namespace can technically encode identifiers; Domain Context explains the semantic universe in which they are used.

## Cross-Layer Relations

It may qualify terminology, classes, properties, quantities, relations, representations, procedures, and documentation. Namespace and terminology semantics remain separate Foundation/Semantics responsibilities.

## Evidence / Provenance

Strongly supported by ISO/IEC 11179 context concepts describing a universe of discourse and the circumstances/purpose/perspective under which an object is defined or used, together with GIOP terminology and architecture analysis.

## Trust / Validation

Validate that the proposed domain identifies a genuine semantic universe and does not merely restate a class, file path, audience, or application task.

## Lifecycle

**CANONICAL — V3.1.**

## Machine / AI Interpretation

Use Domain Context as a scope constraint for retrieval, terminology disambiguation, ontology alignment, and interpretation. Do not infer that a term is invalid outside the named domain merely because the context is domain-specific.

## Retrieval Anchors

`domain context`, `universe of discourse`, `disciplinary context`, `subject domain`, `semantic scope`, `knowledge domain`.

## What This Context Does Not Mean

It is not a visitor profile, organizational department, software namespace, physical environment, or class hierarchy.
