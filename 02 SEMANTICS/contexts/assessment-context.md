# Assessment Context

**GIOP ID:** `SEM-CONTEXT-ASSESSMENT-001`  
**Artifact Type:** Canonical Semantic Concept  
**Status:** CANONICAL  
**Primary Responsibility:** Evaluation frame

## 5W1H Orientation

**What:** The methodological and situational frame in which an assessment or evaluation is conducted.

**Why:** Evaluation results depend on task, material, assessor, procedure, session, anchors, environment, and intended service/use scenario.

**How:** By specifying the relevant assessment design and surrounding conditions needed to interpret the evaluation.

**Where:** Subjective image/video quality assessment, benchmark testing, usability studies, comparative evaluation, standards testing, and service emulation.

**Who:** Assessors, observers, test operators, researchers, QA teams, standards bodies, and automated evaluation systems.

**When:** During an evaluation session or when comparing evaluation results across sessions/settings.

## Canonical Definition

**Assessment Context is a contextual frame specifying the circumstances and methodological setting in which an assessment or evaluation is conducted, including relevant task, test material, assessor or observer, procedure, session, reference/anchor, service-use scenario, and environment.**

## Scope

Assessment Context can contain a Viewing Context where visual viewing is part of the evaluation. It may also include measurement or operational elements, but it is organized around evaluation purpose and method.

## Distinctions

Assessment Context is not Assessment Activity itself, a Viewing Context, a Measurement Context, or an evaluation result. It provides the frame for interpreting the assessment.

ITU-R BT.500 explicitly motivates assessment context for subjective evaluation and service-use emulation; GIOP retains that distinction from generic viewing conditions.

## Cross-Layer Relations

May qualify observers, perceptions, representations, activities, procedures, measurements, results, and quality judgments. Results remain result semantics; observer and perception remain their own layers.

## Evidence / Provenance

Strongly supported by ITU-R BT.500 assessment and viewing methodology and by broader evaluation/benchmarking practice.

## Trust / Validation

Assessment results should be compared only after relevant context compatibility is considered. A common test material does not imply identical assessment context.

## Lifecycle

**CANONICAL — V3.1.**

## Machine / AI Interpretation

Use Assessment Context to qualify benchmark or evaluation results. Preserve task, data/material, protocol, and evaluation setting rather than treating a score as context-free.

## What This Context Does Not Mean

Not the assessment result, test material itself, observer, procedure, or viewing condition alone.
